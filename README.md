# HTEP-001 Catalyst source preservation — v0.2 PR candidate

This is an additive update to the v0.1 source-linked Corpus records for Catalyst IDs `200008`, `800352` and `1400065`.

**New source-byte handoff:** `sources/catalyst/2026-11-05/` contains the four supplied direct-HTTP response bodies, their capture manifest, a short capture-status README, and an offline SHA-256 verifier. The three `projectcatalyst.io` responses contain substantive server-rendered page content and embedded `__NEXT_DATA__` JSON. The `milestones.projectcatalyst.io` response is a JavaScript application shell **without milestone data**, and is preserved only as a failed substantive-capture attempt.

`records/catalyst/source-register.csv` now links captured page observations to their respective SHA-256 hashes and explicitly marks the milestone capture as a shell. Existing project index, observation claims, project READMEs, and monthly/milestone CSVs are retained. Milestone claims still derive from previously observed public rendering, not from this raw response. The original full site records may have changed over time; these captures are from 2026-11-05 UTC.

**Reproduction:** `python sources/catalyst/2026-11-05/verify_captures.py`. This verifies file integrity only, not historical truth or the correctness of observation tables. Existing selective field observations remain source-linked but are not fully regenerated by a deterministic extractor; reviewers should compare source contents against the observations independently.

**Redistribution gate:** confirm site licensing/terms and permission before merging raw HTML into a public repository; if uncertain, stage as PR attachments or retain hashes and source references until resolved. Do not misrepresent direct-HTTP retrieval as a full browser-rendered Milestone Module archive.

The current package deliberately excludes external reports, technical verification, financial reconciliation, and an Orion/Xverse handoff.
